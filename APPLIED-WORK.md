# Applied Work

This file records selected public applications of the research principles without publishing proprietary implementation mechanics.

## AI Systems Capacity Engine

**AI Systems Capacity Engine** is an applied experimental system that tests whether announced AI infrastructure targets can be translated into defensible deployable-capacity claims.

Public repository:

`https://github.com/nandagomesagi/ai-systems-capacity-engine`

Live application:

`https://intelligence.businessaifuture.com`

## Research principles applied

The system operationalizes selected public principles from this repository:

```text
Limits Before Scale
        ↓
Architecture Before Amplification
        ↓
Constraints Before Capacity Claims
        ↓
Dependencies Before Deadlines
        ↓
Evidence Before Assertion
```

Examples of the applied distinctions include:

- `UNKNOWN` is not converted into zero or an invented number;
- announced infrastructure is not treated as deployable infrastructure;
- project-level evidence is not silently generalized into regional capacity;
- unresolved dependencies can block a final deployment claim;
- unsupported lead times remain unknown instead of becoming synthetic critical-path estimates;
- observed evidence, derived results, assumptions, and unknowns remain distinct.

## Why this matters to the research

The applied system does not prove that the conceptual framework is universally valid. It provides a concrete test environment in which the framework can be challenged against infrastructure evidence, dependency chains, scenario assumptions, and incomplete information.

The relationship is:

```text
PUBLIC THESIS
Limits Before Scale
Architecture Before Amplification
        ↓
APPLIED TEST
AI Systems Capacity Engine
        ↓
EVIDENCE OF USE
Does the framework improve constraint visibility,
uncertainty handling, and decision discipline?
```
